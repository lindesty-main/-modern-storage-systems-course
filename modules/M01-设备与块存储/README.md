# M01：设备与块存储

## 模块目标

从块设备接口和地址单位入手，理解主机逻辑请求如何成为设备请求，以及 SSD 内部映射、回收和队列如何影响行为。先区分接口语义、物理介质与可观测结果，再讨论调优；必做实践只使用带格式校验的普通文件映像和纯内存合成模型，不需要裸盘、loop 设备、root、fio、NVMe 硬件或远程服务。

## 前置知识

会使用 Linux shell，理解基本 C/POSIX 文件 I/O 与 LBA 概念；可阅读 Python 3 和 JSON 配置。没有前置的真实存储设备或云账号。

## 完成标准

- 能区分 namespace LBA 大小、Linux logical/physical block size、块层 512 B `sector` 和 NAND page/erase block；不把 LBA 推断为 NAND 物理地址。
- 能解释 LBA 字节偏移与 NVMe NLB/`nblocks` 的零起计数语义，并针对具体接口校验长度/边界。
- 能描述页映射、旧页失效、GC 有效页搬迁、块擦除和空闲空间的关系；会计算模型边界内的写放大。
- 能区分动态/静态磨损均衡与 GC 策略，理解擦除计数不是设备寿命预测。
- 能解释请求合并/拆分、队列深度、服务能力和排队延迟，并比较本地/远程块存储路径与故障边界。
- 通过 [L01 块映像实验](../../labs/lab-01-block-image/README.md) 的 `make clean all test` 和 [L02 FTL/队列实验](../../labs/lab-02-ssd-ftl-model/README.md) 的标准库 `unittest`。
- 报告实验时标明命令、配置和本机 Python/编译器/内核信息；说明模型未模拟 SSD 固件、硬件性能、持久性或候选课程环境集成验证。

## 安全与结果边界

M01 必做实验禁止向真实块设备、分区、裸 NVMe 或 loop 设备写数据。不得把 `/dev/nvme…` 作为 `dd`、`cat`、原始 ioctl 或内核模块实验的默认目标。L01 只操作程序创建并校验格式的普通文件；L02 仅在内存中运行合成 FTL 和队列，不打开设备、不运行 fio、不访问网络。模型值不是实际 IOPS、延迟、WA、TBW、耐久性或 SLA 证据。任何后续设备级扩展实验必须单独审核权限、目标隔离、设备可丢弃性和恢复方案，且不能替代普通文件/合成模型主线。
