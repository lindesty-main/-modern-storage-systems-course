# M06：索引与内存管理

## 模块目标

本模块从 M05 的 KV 数据路径继续：选取数据结构时同时考虑点查、更新、范围扫描、可预测的复杂度和内存开销；理解索引节点如何分配与回收，以及缓存淘汰为什么改变命中率但不能代替一致性协议。课程覆盖 slab、哈希、红黑树、跳表、加锁及组件集成，并明确理论假设和实现边界。

配套程序是 [`IndexCacheLab`](../../projects/IndexCacheLab/README.md)：纯 C++20、无第三方依赖/设备/网络的哈希、跳表、树索引正确性对照，以及固定种子轨迹上的 LRU/FIFO 缓存策略比较。测试比较精确结果，不用墙钟跑分。

## 前置与边界

- 前置：M05 KV API/WAL/LSM 的基本概念；熟悉 C++、容器、指针/对象生命周期与渐进复杂度。
- 默认实验仅在本地用户进程中使用内存数据；不访问 MiniStore、块设备、SPDK、真实 SSD、网络或用户数据目录。
- 样例索引均为单线程教学实现，不提供并发安全、持久化、崩溃恢复、资源配额或恶意输入保护。`std::map` 只承诺标准规定的复杂度，标准不要求其内部必定采用红黑树。
- 命中率实验是固定合成轨迹的内存模拟，不是硬件基准；不测纳秒延迟、吞吐、RSS、OS 页缓存或数据库端到端表现。

## 自动验收

```sh
make -C 'projects/IndexCacheLab' clean test
```

验收包含：

- 哈希/跳表/有序树对共同 API 行为一致：覆盖、未命中、删除、半开范围 `[lower, upper)`；对固定种子 4,000 次操作与有序参考模型逐项核对。
- 缓存容量为 3 的短轨迹检验 FIFO/LRU 更新规则差异；容量为 0 时全部 miss。
- 12,000 次固定访问轨迹必须有固定 FNV-1a 校验和 `766801a21e475d3a`；容量 32、冷启动下 LRU 为 8,251 hits，FIFO 为 8,243 hits。命中率是这条特定轨迹的验收结果，不是普遍优劣结论。
- 构建报告包括编译器/标准级别、固定索引工作负载与策略计数；不输出或宣传耗时性能。
