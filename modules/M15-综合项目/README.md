# M15：MiniStore 综合项目

## 模块状态与定位

M15 是课程最后 3 课，把 M05 的 KV/WAL、M07 的进程级故障注入、M08 的本地对象 API、M12 的基准方法与 M14 的安全边界收束到同一份 MiniStore 项目。三课课文、项目 CI 式测试和可在普通 Linux 主机上复现的发布演练均已完成。

**模块课文完成不等于候选软件栈都通过集成验证。**本地 C++20/Python 项目在当前机器上的构建与测试结果，只能描述该次本地验证；SPDK、真实 SSD/NVMe、Ceph/RGW、AWS、Kubernetes/CSI、特定课程发行版及其他未运行候选组合仍是可选或未验证项目。必做路径不依赖这些组件。

## 学习目标

完成本模块后，学员能够：

1. 画出 MiniStore 的 CLI、KV/对象 API、独占锁、内存有序 map、WAL、SSTable 与恢复路径；说明模块边界和现有错误契约。
2. 从 M05 → M07 → M08 → M12 的阶段成果建立端到端验收：单条写入、错误返回、重新打开、compaction、恢复、正确性校验和负载观察各有独立 oracle。
3. 区分进程退出、OS/主机崩溃和设备掉电；理解同步错误/响应丢失时的结果不确定性，不把 SIGKILL 测试误称为断电认证。
4. 按项目声明的单进程模型验证锁冲突，拒绝将 fail-fast 约定误读为并发服务能力。
5. 生成可复现、带数据校验和分位数的**本机 CLI 观察报告**，解释启动、恢复、锁和 `fdatasync` 都包含在测量路径里。
6. 产出发布清单与限制复盘；明确不声称生产安全、S3 兼容、分布式一致性或硬件/云/Kubernetes 能力。

## 环境与安全

- 必做：Linux、兼容 C++20 的 G++、GNU Make、Python 3 标准库。项目无第三方库、无 root、无网络服务、无设备路径参数。
- 可选硬件/云/Kubernetes 功能均以本机临时目录、合成轨迹、进程故障和纯文档设计替代；不要为完成课程连接真实云服务或挂载集群。
- 所有手工演练都只允许写入本次 `mktemp` 新建的私有目录。`init` 不会复用现存目录；不要将清理变量改成仓库、用户目录或真实数据库。
- MiniStore 是**单机、单进程持锁的教学原型**，第二个进程立即失败；不是生产级数据库或对象服务。它没有网络监听、S3/SigV4、生产 AuthN/AuthZ、多租户、加密/密钥管理、备份/灾备、复制、分布式一致性或硬件掉电认证。
- M07 测试只 SIGKILL 用户态进程；OS、页缓存、文件系统及设备仍运行。CRC32 只检查偶发损坏，不是密码学认证。

## 从仓库根目录一键本地门禁

```sh
make -C 'projects/MiniStore' ci
make -C 'projects/MiniStore' clean
```

`ci` 先删除项目自己的 `build/`，再编译正常 CLI 和带测试 failpoint 的 CLI，执行所有 Python 黑盒/基准测试。所有数据库位于测试私有临时目录并由清理器删除。`clean` 只移除本项目 `build/`。项目 `.gitignore` 忽略 `/build/`，构建二进制不得提交。

详细项目契约、命令、存储格式与边界见 [MiniStore README](../../projects/MiniStore/README.md)；M07 故障矩阵见 [Lab 06](../../labs/lab-06-crash-consistency/README.md)，M08 对象契约见 [Lab 07](../../labs/lab-07-object-api/README.md)，M12 观测口径见 [Lab 12](../../labs/lab-12-performance-benchmark/README.md)。
