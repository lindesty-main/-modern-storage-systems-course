# M15-L01：架构、接口契约与阶段集成

## 目标与先修

本课把前面分别学过的接口、WAL、恢复、对象 API 与性能验证变成同一个可验收项目。学完后能够从一次 `object-put` 或 KV `put` 追踪到锁、验证、WAL、同步、内存索引和后续恢复；能够列出功能成功/失败的可观察行为；能区分已集成代码、纯模型实验与尚未验证的候选栈。

先修：[M05 本地 KV 引擎](../M05-本地KV引擎/README.md)、[M07 持久性与崩溃一致性](../M07-持久性与崩溃一致性/README.md)、[M08 对象存储服务](../M08-对象存储服务/README.md)、[M12 性能工程](../M12-性能工程/README.md)。建议先运行项目 [CI 门禁](../../projects/MiniStore/README.md#构建与自测)。

## 项目目标不是“造一个生产对象服务”

课程综合项目以一个受限 MiniStore 代码库为共同落点。已有实现范围是：本地目录、显式 KV 和对象 CLI、单进程独占锁、append-only WAL、进程内有序 map、一个 SSTable、手动 compaction。对象 API 是本地命令行子集；不实现 HTTP、S3 REST、SigV4，也没有对象策略、metadata 自定义字段或 multipart。

最终验收关注契约可说明、数据可读回、恢复路径可测试、性能观察可复现、限制诚实。它不以功能数量、绝对吞吐或“像云服务”为成功标准。硬件、云、Kubernetes/CSI 有本地替代：普通临时文件和本机进程、测试故障挂点、合成负载与标准库报告。选修软件栈仍需各自版本/环境验证，不能由本项目测试代替。

## 架构及请求路径

```text
命令行 / 本地对象 CLI
  ├─ 参数解析、key/bucket/value 限制、退出码
  └─ 每条命令打开一个数据库实例
        │
        ├─ canonical parent + openat / O_NOFOLLOW
        ├─ FORMAT 校验、目录/文件 mode/owner 检查
        ├─ LOCK: flock(LOCK_EX | LOCK_NB)，失败即返回
        ├─ 读 TABLE.sst → 校验版本/长度/CRC/顺序
        ├─ replay WAL → 校验 magic/CRC/sequence；仅修复不完整末尾
        └─ 查询或写入
             ├─ KV put/delete ─┐
             └─ object put/delete ─ 内部 @obj:<bucket>:<key> 键
                                │
                 encode record → append WAL → fdatasync
                                │
                 更新 ordered map → 返回成功

list/object-list: 全量扫描内存 map
compact: map → TABLE.sst.tmp + fdatasync → rename + dir fsync
         → WAL.tmp + fdatasync → rename + dir fsync
```

关键点：一个 CLI 命令通常就是一个短命进程。每个请求都会打开数据库、取锁并重放状态；成功的 put 在 WAL 同步成功之后更新内存并返回。写入同步错误、同步后客户端未收到响应，可能结果不确定；调用方应重新打开并查询，不可根据失败响应推断“绝对没写入”。`flock` 是协作式的单实例互斥，不提供排队、并发服务或跨主机租约。

## 四个阶段如何集成

| 来源/阶段 | MiniStore 集成点 | 综合验收 oracle | 不得夸大的结论 |
|---|---|---|---|
| M05 KV/WAL | `put/get/delete/list`、序号、WAL、内存 map、SSTable、compact | 覆盖/空值/删除/排序、重新执行 CLI 后读回；CRC/长度错误拒绝 | 不等于 RocksDB、多层 LSM、批事务或任意规模引擎 |
| M07 持久性/故障注入 | 测试专用 binary 在 WAL append/sync 与 table/WAL rename 边界暂停，测试杀用户进程 | 只截断结构不完整尾部；完整损坏 fail closed；重新打开后状态与后续写入正确 | SIGKILL 不模拟 OS/主机/设备掉电；合成 EIO 不模拟真实硬件 |
| M08 对象 API | `object-put/get/delete/list`，bucket/key 校验与 KV 不冲突的内部 namespace | 二进制/空对象、覆盖、桶隔离、prefix、大小边界、删除/缺失码、compaction/reopen | 不是 S3、HTTP、SigV4、multipart 或跨对象事务 |
| M12 性能验证 | 先校验值，再记录 CLI 操作 latency、重复运行、百分位、工作负载 seed 与环境 | MiniStore 自带受界限 benchmark JSON；Lab 12 独立测本机普通文件/缓存轨迹 | 本机 CLI latency 不是设备 IOPS、云性能、生产服务容量或硬件对比 |

M15 补充的集成回归会先写 KV manifest 与二进制对象，再覆盖 manifest、compact，然后在新的 CLI 进程读取两者；还断言普通 `list` 不暴露内部对象键。这是阶段组合的正确性用例，不引入新的持久化格式或服务端接口。

## 接口契约检查表

| 操作 | 输入/成功行为 | 失败边界 |
|---|---|---|
| KV `put/get/delete/list` | 1–128 ASCII key；put 整值 upsert；空 value 合法；list 按字节序返回 hex | 非法参数/输入退出 2；存储/锁/IO/格式退出 1；缺失 get/delete 退出 3 |
| Object put/get/delete/list | 桶为 1–63 ASCII 字母数字；对象 key `[A-Za-z0-9._-]`；stdin/stdout 原始 bytes；对象最大 1 MiB；list 输出 key/size | 不接受 `/`、空格及任意 Unicode；非法/超限退出 2；缺失退出 3；锁/IO 退出 1 |
| `init` | 最末级路径不存在，创建私有目录及格式文件 | 绝不覆盖现存目录；父目录须存在；初始化中断留下的目录需人工检查 |
| `compact` | 发布单个排序快照、清 WAL、排除墓碑 | WAL 达 64 MiB 时写入拒绝并提示压实；错误后必须重新打开和检查 |
| 并发 | 所有命令尝试取得数据库独占 flock | 第二个进程立即失败；不排队、不保证并发读写或公平性 |

接口的权威细节、容量口径、返回格式和存储格式以 [项目 README](../../projects/MiniStore/README.md) 与 CLI 自动测试为准；不要在项目外文档复制一份有差异的“协议”。

## 阶段集成练习（命令可复制）

从仓库根目录执行只会创建/清理本次新建目录的流程：

```sh
make -C 'projects/MiniStore' ci
make -C 'projects/MiniStore' clean
```

`ci` 强制重建 release/test 二进制后运行所有黑盒测试。详细的混合 KV/对象接受脚本与进程故障矩阵在 [M15-L02](M15-L02-端到端正确性、重启与验收演练.md)。报告生成器与指标解读在 [M15-L03](M15-L03-基准报告、发布清单与限制复盘.md)。

实现导读：`Store::append_operation` 对应 M05/M07 写入提交边界；`Store::recover_wal` 与 `load_table` 对应恢复/校验；`Store::compact` 对应 snapshot 与 WAL 轮换；对象方法复用同一存储状态但保留 namespace；`bench_ministore.py` 作为外部 CLI 客户端观察端到端路径，不作为引擎内部 microbenchmark。

## 结果解释与常见误区

1. **“同步成功就是任何断电都不丢。”**不成立。应用只请求本地 `fdatasync/fsync`；是否落到非易失介质取决于内核、文件系统、驱动、设备缓存和硬件保证。课程没有真实掉电试验。
2. **“对象接口有 bucket/key，所以兼容 S3。”**不成立。项目没有 HTTP、S3 操作语义、签名、认证/授权、分页 token、multipart 和 AWS 产品承诺。
3. **“有 flock，所以支持并发。”**不成立。这里只是避免两个遵守协议的进程同时打开；竞争者被快速拒绝，没有服务并行模型。
4. **“M12 的文件 benchmark 就是 MiniStore 性能。”**不成立。M15 的 CLI 工具包含 subprocess 启动、全 WAL replay、锁、解析、同步与响应输出。Lab 12 则是另一种 buffered regular-file 模型；报告不可把两种路径混成对照排名。
5. **“34 课正文完成即全栈验证完成。”**不成立。正文进度、课程模型测试和某个候选发行版/外部软件栈集成验证是不同证据等级。
