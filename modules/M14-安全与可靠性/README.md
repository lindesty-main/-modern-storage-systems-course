# M14：安全与可靠性

> 状态：1 课正文与 Lab 14 本地安全审计实验已完成。必做部分仅使用标准库和自建临时目录；不联网、不需要 root、不扫描服务、不访问裸盘或用户数据。该模块讲解工程控制与威胁建模，不构成产品安全审计/认证。

## 模块目标

- 编写存储威胁模型：资产、威胁主体、信任边界、攻击路径、影响和残余风险。
- 区分身份认证与授权；设计默认拒绝、最小权限、租户隔离和审计策略。
- 识别输入、路径/符号链接、文件权限、校验和、密钥和静态数据保护边界。
- 评估依赖、构建与发布供应链；设计离线/隔离备份、密钥恢复和恢复验收。
- 对删除、重建、格式化、权限/密钥修改和恢复覆盖等危险操作进行范围审查。
- 准确说明 MiniStore 和设备实验未实现的生产安全能力。

## 完成标准

- 能把数据/WAL/索引/密钥/依赖/备份/审计证据列为不同资产，并明确各自保密性、完整性、可用性目标。
- 能画出客户端、身份系统、服务、租户、主机/文件系统、密钥、备份与构建发布之间的信任边界。
- 能解释认证建立 principal、授权决定主体对资源/动作的许可；知道请求中的 tenant 字符串不是认证身份。
- 能为越权读/列/删、路径穿越、symlink/TOCTOU、损坏记录、密钥失效、依赖失陷和误删写出可测试控制与剩余风险。
- 能区分 mode bits、CRC/hash、HMAC/AEAD 的保护能力；说明加密数据需要密钥恢复，快照不是独立备份。
- 能提出供应链库存/锁定、SBOM、来源/签名、漏洞处置与受限构建的检查项。
- 能在演练中恢复到隔离新目标并校验数据和应用约束；高风险写操作有目标、范围、备份、批准、回滚/停止和审计证据。
- 能明确说出 MiniStore 没有身份认证/授权、多租户隔离、静态/传输加密、密钥管理、不可变异地备份、安全审计、供应链证明或生产安全认证。

## 安全边界与限制

Lab 14 只使用临时私有普通目录/文件、合成 bytes 和标准库；不接收用户目标路径、网络地址或设备参数，不扫描、不连接、不挂载、不提权、不删除外部数据。脚本通过目录 fd、`O_NOFOLLOW`、`O_EXCL`、owner/mode/regular-file 检查展示 Linux 本地防线，但不是完整安全文件服务。

Lab 中 principal 是传入的 tenant label，非密码/证书/token 认证。SHA-256 是无密钥校验，不能防有意改写者；mode bits 不隔离同 UID/root；自动化测试只证明用例和当前环境行为。MiniStore 本身为单机教学原型，不能用于生产、敏感数据或多租户服务，具体缺项见课文及[项目边界](../../projects/MiniStore/README.md)。
