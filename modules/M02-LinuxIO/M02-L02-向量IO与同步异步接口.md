# M02-L02：向量 I/O 与同步、异步接口

> 状态：正文完成　｜　建议课时：100–110 分钟　｜　依赖：M02-L01；熟悉 C 数组、指针与 POSIX 文件描述符。必做实践仅操作程序创建的普通临时文件与本地 `AF_UNIX socketpair`。

## 学习目标

学完后，你应能：

1. 用 `struct iovec` 描述 scatter/gather 缓冲区，并正确理解 `readv`/`writev` 的部分完成语义。
2. 区分“同步/异步”“阻塞/非阻塞”“就绪/完成”，不将这些术语当作同一维度。
3. 对比 `readv`/`writev`、`sendmsg`/`recvmsg`、`epoll`、POSIX AIO 和 `io_uring` 的抽象差异。
4. 说明向量 I/O 减少的是什么开销、哪些复制仍可能发生，以及它为何不自动形成记录边界或消息边界。
5. 在本地实验中验证分段顺序、短传输处理和 socket 字节流语义。

## 为什么需要向量 I/O

应用常把逻辑数据拆成若干段：协议头、固定字段、payload、尾部校验。若先把多段缓冲区拼进一个新 buffer，再调用 `write`，需要额外分配和复制；若逐段调用 `write`，会增加系统调用次数。向量 I/O 给内核一个有序的 buffer 列表，适合把分散的内存段作为一个逻辑读写请求提交。

```text
应用内存：  [header] [metadata] [payload]
                 │       │         │
                 └───────┴─────────┴── writev(fd, iov, 3)
                                         一次调用的有序字节流
```

`struct iovec { void *iov_base; size_t iov_len; }` 描述一段内存。`writev` 将各段按数组顺序写出；`readv` 把输入字节依序填入各段。相同的 scatter/gather 结构也可通过 `sendmsg`/`recvmsg` 与 socket 使用。Linux 有每次向量数上限（可用 `sysconf(_SC_IOV_MAX)` 查询）；长度总和还须在 `ssize_t` 与应用缓冲区边界内。

向量 I/O 可省掉应用层拼接 buffer 或合并多个 syscall 的一部分成本，但它不是“零拷贝”：普通文件读写仍可能把数据在内核页缓存与用户缓冲区间复制；网络栈也有自身的缓冲和复制。是否减少 CPU 开销取决于段数、尺寸、系统调用批量程度、缓存/网络路径和测量方法。

## 部分完成：返回的是总字节数，不是“第几个 iovec”

`readv`/`writev` 的返回值是本次传输的**总字节数**。这次结果可能只覆盖 iovec 数组的前几段，或在某一段中途结束；内核不会返回“成功了第几段”的标志。比如向量长度为 `[5, 8, 4]`，返回 10 表示前 5 字节和第二段的前 5 字节已经传输。后续重试应从第二段偏移 5 处开始，而不是从原数组开头重发。

健壮的完整传输 helper 通常需要：

1. 校验 `iovcnt`、总长度、非零长度的 base 指针和总量溢出；
2. 保存一份可修改的 iovec 游标，避免破坏调用者的原始描述；
3. 每次调用后累计正向字节数，跳过已耗尽的 iovec 并推进当前段的 base/len；
4. `EINTR` 时按接口条件重试，其他错误返回；零字节进展在非零剩余长度时视为 EOF/异常，不能无限循环。

对本地 `SOCK_STREAM`，一次 `writev` 可能对应多次对端读取；一次 `readv` 也可能读到不完整的应用记录。TCP/stream 本身没有消息边界。应用协议必须自行定义长度前缀、固定长度、分隔符或其他 framing，接收端还要积累完整记录。对于 datagram，消息边界由传输层保留，但单个数据报长度受限，过大的消息可能截断/失败，规则不同。

## `sendmsg` / `recvmsg` 不只是 vector I/O

`sendmsg` / `recvmsg` 的 `struct msghdr` 可同时携带 iovec 数组、目标地址/对端地址和 ancillary control messages。Unix 域 socket 可以通过 `SOL_SOCKET` / `SCM_RIGHTS` 传递文件描述符。传递的是内核管理对象的引用，接收进程获得自己进程表中的 fd；不是复制指针，也不是把共享内存内容复制进控制消息。共享内存如何建立、fd 的访问权限、映射生命周期和进程同步仍由程序负责。

安全处理控制消息时，应按 `CMSG_FIRSTHDR` / `CMSG_NXTHDR` 遍历并检查 `cmsg_level`、`cmsg_type`、`cmsg_len`；接收端要处理 `MSG_CTRUNC`，并可用 `MSG_CMSG_CLOEXEC` 请求新 fd 设置 close-on-exec。描述符传递不等于数据传递，权限也不因使用 socket 自动变得更安全。

文件或网络数据是字节序列，不保证以 NUL 结尾；`readv` 不会补 NUL。应依据实际返回字节数输出（如 `fwrite`），或在明确容量范围内自行终止。使用 SCM_RIGHTS 传 fd 时，实验应创建权限受控且无命名冲突的本地 socket；本课程 Lab 使用匿名本地 `socketpair`，不创建网络监听端口或共享名字。

## 同步与异步是完成通知方式

**同步调用**在本次调用返回时带回本次操作结果；若尚无结果，调用可能等待，也可能立即返回错误/部分结果。**异步接口**把操作提交后先返回，稍后由完成事件、回调或完成队列交付结果。它描述的是操作发起者如何获知完成，不等于有无并发、是否多线程或是否绕过内核。

**阻塞/非阻塞**描述调用在没有进展时会不会等待。例如 `O_NONBLOCK` 下 `read` 可能立即返回 `EAGAIN`；这并没有把一次 read 变成异步完成操作，只是让应用在等待数据期间可以做别的事。**就绪通知**告诉程序“现在可以尝试读/写”（典型 `poll`/`epoll`），程序还要调用实际 I/O；**完成通知**告诉程序“已提交的这个 I/O 已完成”，并给出结果（如 `io_uring` CQE）。

| 接口/模式 | 程序交给内核的内容 | 通知与结果 | 常见优点 / 代价 |
|---|---|---|---|
| `read`/`write`、`pread`/`pwrite` | 当前立即执行的一次 I/O | 调用返回字节数或错误；调用可能等待 | 简单、易调试；无独立操作可重叠时往往够用 |
| `O_NONBLOCK` + `poll`/`epoll` | fd 与感兴趣的就绪条件 | 收到“可尝试”事件，再由应用读/写 | 管理大量连接；每次事件后仍需处理部分 I/O 与状态 |
| POSIX AIO | 提交异步控制块 | `aio_error`/`aio_return` 或信号/通知 | 标准化接口；实现/文件类型限制和使用复杂度需核对 |
| Linux native AIO / libaio | Linux AIO 请求队列 | 取回完成事件 | 历史上适用范围和 buffered/direct 语义有约束；不是通用网络 I/O 的同义词 |
| `io_uring` | SQE 操作请求 | CQE 完成项 | 可批量提交/收割多类操作；需要管理队列、生命周期和内核能力 |

这张表描述的是接口模型，不是性能排名。同步 I/O 如果缓存命中、数据很小或仅一个请求，额外队列和状态机可能没有收益；当多个独立请求可以同时等待时，异步接口可能隐藏一部分等待时间。应用仍受 CPU、内存带宽、设备队列、文件系统和服务端能力限制。

## 缓冲区和状态的生命周期

对异步提交，操作关联的 fd、buffer 和应用自有状态必须在完成前保持有效；不可在 CQE 到达前释放、复用写 buffer、关闭仍被操作依赖的资源或把同一 buffer 分配给另一个并发操作。完成顺序可能不同于提交顺序，应通过请求 ID/token 关联业务状态；不可仅凭“收到第 N 个完成”推断它对应“第 N 个请求”。取消请求也不代表操作已经停止，仍要处理其最终完成/取消结果。

这些约束同样出现在同步程序中，例如 `readv` 的 iovec 内存须在调用期间有效；只是同步调用在返回前仍由当前线程负责等待。异步接口把生命周期从“一个函数调用”扩展到了“提交到完成”的区间。

## 实验：用向量 I/O 验证语义

关联实验：[Lab 03：Linux 文件与本地 socket I/O](../../labs/lab-03-linux-io/README.md)。运行：

```sh
make clean test
```

默认 C 程序把三段字节用 `writev` 写进自己创建的临时普通文件，再用不同边界的 `readv` 读回；同时验证 `pread`/`pwrite` 不推进共享偏移。它用 `socketpair(AF_UNIX, SOCK_STREAM, ...)` 在同一进程的本地 socket 端点间传递短消息，验证分段向量最终是有序字节流。完整传输 helper 处理 EINTR、短传输和零进展，并对过多向量、空描述和负偏移做拒绝测试。

没有外部客户端、监听端口、root、原始设备、fio 或第三方库依赖。临时文件在程序内部生成并限制为普通文件；自动测试退出时会检查私有临时目录已清理。这个实验验证接口与正确性，不测量网络吞吐、磁盘延迟、零拷贝或持久性。

## 常见误区

- **“`readv` 一次就把每段填满。”** 错；返回总字节数，可能只填充向量的一部分。
- **“`writev` 会替应用保证一条完整消息。”** 错；stream socket 没有应用消息边界，仍需 framing；完整传输 helper 也不等于事务原子性。
- **“scatter/gather 就是零拷贝。”** 错；它避免某些用户态拼接/拆分，不代表内核数据路径没有复制。
- **“非阻塞就是异步。”** 错；非阻塞通常让调用立即返回当前状态，仍需应用重试/等待；异步接口会在完成后另行通知结果。
- **“`epoll` 告诉我一次 read 已完成。”** 通常不是；它通知就绪，应用仍要发起并处理实际读写。
- **“收到异步完成顺序就是提交顺序。”** 错；用 token 匹配请求，维护每个 buffer 与状态的生命周期。
- **“传递 fd 就等于共享了内存指针。”** 错；SCM_RIGHTS 传 fd 引用，接收进程仍需按对象类型映射/使用并负责权限与关闭。
