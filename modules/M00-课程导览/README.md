# M00：课程导览与存储全景

## 模块目标

先建立共同语言，再开始设备、IO 和存储服务的专题课。学员将从业务请求追踪到本地介质或远端服务，区分存储接口、设备协议、介质和故障域；把模糊的性能/可靠性诉求写成工作负载、SLO、故障假设和待确认问题；完成不触碰真实设备的环境只读自检与需求卡实验。

本模块不教授生产环境容量规划或产品选型定论，也不声称候选 OS/内核版本已经集成验证。图示是教学模型；接口、缓存、完成/持久化语义必须按具体产品版本、配置和故障模型核对。

## 前置知识与环境

- 前置：基本 Linux 命令行和应用 API 概念；M00-L02 实验需 Python 3 标准库。
- 不要求：NVMe/裸盘、root、虚拟化软件、云账号、公网连接或第三方 Python 包。
- 课程候选主线环境和版本边界见[版本与实验环境](../../课程大纲/版本与实验环境.md)。候选组合是规划基线，不是当前实验已在该组合上集成通过的证明。
- 安全原则：M00 实验只读取主机身份信息与需求 JSON；测试数据只写入自动清理的临时目录。不格式化、挂载、扫描或写入块设备，不安装软件、不启动服务。

## 实验与验收

实验和脚本集中在 [`labs/lab-00-storage-requirements/`](../../labs/lab-00-storage-requirements/README.md)。在仓库根目录运行：

```sh
cd 'labs/lab-00-storage-requirements'
python3 -B m00_preflight.py check
python3 -B m00_preflight.py validate requirement-card.example.json
PYTHONDONTWRITEBYTECODE=1 python3 -B -m unittest -v test_m00_preflight.py
```

完成标准：

1. 在数据路径图上分别标明普通文件缓存命中/未命中、一个远端路径和一次写入确认点；明确 API 返回不自动等同掉电持久。
2. 能解释工作负载比例的计数口径以及吞吐/尾延迟、可用性/耐久性、复制/备份的差异。
3. 成功运行 `PYTHONDONTWRITEBYTECODE=1 python3 -B -m unittest -v test_m00_preflight.py`，并根据自己的场景填写实验临时副本的需求卡；不修改示例文件。
4. 报告环境信息、需求来源/估算、故障假设、目标 SLO、待确认项及实验限制；不得把 JSON 校验或本机自检写成产品/性能/HA 验收。
